# Example Architectural Decision Records

This directory contains example ADRs to demonstrate the style and structure 
used in Chronicle projects.

Each ADR demonstrates a different aspect of architectural decision-making 
and provides a template for how to document decisions in your own projects.

## ADR Structure

Each ADR follows a consistent format to ensure clear communication of decisions:

1. **Title**: A noun phrase describing the decision
2. **Date**: When the ADR was created
3. **Status**: Proposed, Accepted, Deprecated, or Superseded by ADR-XXXX
4. **Context**: The problem that motivates the decision
5. **Decision**: What was actually decided
6. **Consequences**: What becomes easier or harder because of this change
7. **Alternatives Considered** (Extended templates only): Other approaches and why they were rejected
8. **Rationale** (Extended templates only): Why this specific decision was made

These examples show how to document decisions that are concrete, actionable, and 
help maintain architectural integrity over time.
